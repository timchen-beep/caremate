## 2. 配置（三种方式，优先级从高到低）

```bash
# 1) 环境变量（联调最方便）
export YIBAN_API=http://192.168.1.20:8400    # 电脑的局域网地址
export YIBAN_TOKEN=app-elder-001              # 后端 init_db 写入的演示令牌

# 2) 桌面运行（Qt 6.11）
cmake -S . -B build-desktop -DCMAKE_PREFIX_PATH=/opt/Qt/6.11.1/gcc_64
cmake --build build-desktop -j6
./build-desktop/yiban_android_app
```

3) 配对：设置页输入 6 位配对码 → `DeviceVM.pair()` → `POST /v1/pair` → 令牌写入 QSettings，
   之后所有请求自动带 `X-Token`。

> Android 模拟器访问宿主机用 `http://10.0.2.2:8400`（默认值就是它）。

## 3. 同步语义（与后端对齐）

| 动作 | 端上 | 后端 |
|---|---|---|
| 启动 | 拉 `/v1/plans?since=0` → 拉 `/v1/state?since=cursor` | 计划全量、实例全量 |
| 每 15 秒 | 有待传事件先上传，否则拉状态 | `/v1/state` 增量 |
| 每 60 秒 | 拉计划 | `/v1/plans` 全量（量小，直接覆盖） |
| 用户点确认/推迟/撤销 | 写本地事件（`serverSeq=0`）→ 触发上传 | `/v1/events` → 回 `server_seq` → 端上置已同步 |
| 到点升级/呼救 | `DeviceVM` 触发 → `POST /v1/alarm` | 后端 `sos()` / `raise_alarm()` |
| 断网 | `syncState="offline"`，退避 1s→2s→4s→…→5min | — |

**冲突**：后端回 409（`state_conflict`）时以服务端为准，`SyncEngine` 会把状态置 `error` 并提示，
随后下一轮拉取会用服务端状态覆盖本地乐观值。

## 3.5 本地主副本（新增）

`src/vm/local_store.cpp` 用 QtSql 开 SQLite（WAL），四张表 + 一张 meta：

| 表 | 内容 |
|---|---|
| `plans` | 计划 JSON（`planId` 主键） |
| `occurrences` | 实例 JSON（`occurrenceId` 主键） |
| `records` | 记录 JSON（`recordId` 主键） |
| `events` | 事件 JSON + `server_seq`（`event_id` 主键） |
| `meta` | `server_seq` 增量游标 |

`AppCore` 的行为变化：

1. **冷启动**先 `open()` + `load()`：有本地数据就直接用（断网也能看到今天的提醒），没有才 `seedDemo()`
2. **每次变更**（确认/推迟/未确认/新建计划/记录/远端灌入）触发 `touchPersist()`，1 秒防抖后整表快照写盘
3. **游标持久化**：`serverCursor()` / `setServerCursor()`，重启后从上次位置继续增量拉

## 5. 编译时可能踩的坑

1. `SyncEngine` 用了 `qobject_cast<QNetworkHttpClient *>`，`QNetworkHttpClient` 必须带 `Q_OBJECT`（已带）。
2. `AppCore::applyRemotePlans` 会触发 `rebuildToday()`，它依赖 `m_day`；引擎在启动后第一帧才有日期，因此
   首次拉取前若 `m_day` 无效，实例会被重建为空——真机上表现为"首页空一秒后自动出现"，可接受。
3. 若后端返回 401，先确认 `YIBAN_TOKEN` 与后端 `users.token` 一致（默认 `app-elder-001`）。
