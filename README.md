# CareMate · 网页端路线

这个分支**只有网页端路线**：一个 Python 后端 + 三个网页（老人端 / 家属看板 / 大屏 kiosk）+ 一个 PWA。
没有 Flutter、没有 Qt、没有硬件固件与系统改造脚本——那些在 `main` 与其他归档分支里。

> 以后网页端的迭代都在这个分支做：`main` 只作为整合版保留。

## 1. 一分钟跑起来

```bash
cd server
python3 server.py --port 8000
# 老人端      http://127.0.0.1:8000/app
# 家属看板    http://127.0.0.1:8000/dashboard
# 大屏 kiosk  http://127.0.0.1:8000/kiosk
# 首页        http://127.0.0.1:8000/
```

零第三方依赖：只要有 Python 3.9+（`sqlite3` / `http.server` 都是标准库）。

## 2. 这个分支里有什么

| 路径 | 作用 |
|---|---|
| `server/server.py` | 唯一后端：规则展开、实例物化、状态迁移、三档升级链、统计、备份、页面路由、端云同步 |
| `server/v1_adapter.py` | 手机端 `/v1/*` 契约适配层（后端仍由它 import，保留以免服务起不来） |
| `server/web/` | 四个页面 + PWA 清单/Service Worker/图标 |
| `server/test_*.py` | 九套验收（契约、可靠性、一致性、步骤、离线、扩展、同步、手机端契约、验收） |
| `docs/` | 接口口径、验收清单、部署、演示脚本、4.2 报告正文 |
| `tools/` | `verify_all.py`（21 项全量验证）、`publish.py`（验证+提交+推送）、索引生成、P95 采样、证据汇总 |

## 3. 改完怎么发

```bash
python tools/publish.py            # 验证 21 项 → 逐文件提交 → 推送本分支
```

验证不过不会提交；提交信息是 `<路径>：<该文件「作用」注释>`。

## 4. 验收

```bash
python tools/verify_all.py
```

依次检查：截断守卫 → 二进制魔数 → 语法 → 起服务 → 九套验收 → 产物卫生 → 构建引用 → 四个页面 → 文档数字一致。

## 5. 设计上要知道的三件事

1. **唯一状态入口** `transition()`：任何接口都不直接写 `occurrences.state`。
2. **三次升级**：到点 `notified` → 2 分钟 `escalated`（通知家属）→ 5 分钟再提醒 → 15 分钟 `missed`。
3. **接口前缀**：网页与看板用 `/api/v1/*`，手机端用 `/v1/*`（同一真相来源，两套壳）。

## 6. 与 main 的关系
