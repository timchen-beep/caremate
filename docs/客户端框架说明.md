# 客户端框架：4.1 是 Qt，不是 Flutter

## 1. 一句话

**4.1（手机端）的交付物是 Qt/QML。** Flutter 版是我们早期的验证实现，不参与交付。

## 2. 依据（不是我们拍的）

| 来源 | 内容 |
|---|---|
| 报告 4.2 草稿注记 | "this file is only the 4.2 block of Section 4, and **the mobile client (4.1) is written separately by the app group**" |
| `手机App技术架构图-竖版.docx` | Qt 6.11 / QML 五层架构，包名 `com.yiban.elder` |
| `fspro7967/yiban_android_app` | 实际代码：Qt 6 + QML + C++17，`CMakeLists.txt` 里 `find_package(Qt6 ... Quick Qml TextToSpeech Network Sql)` |
| 他们的 `docs/端上接口规范_v1.1.md` | 端上契约（int64 id、毫秒时间戳、6 状态机） |

报告正文（4.2）里**从未出现 Flutter 或 Qt**——4.2 只写云端与看板，客户端框架由 4.1 决定。

## 3. 两套代码的定位

| 路径 | 技术 | 定位 |
|---|---|---|
| `qt/` | Qt 6 / QML | **交付路线的参考实现**：`net/HttpClient` + `net/SyncPuller` 已接 `/v1/*`；`core/ReminderModel` 负责规则展开与事件入队 |
| `integration/yiban_client/对接后端.patch` | 给 app 组仓库的补丁 | 把他们的 Qt 客户端接上我们的后端（真 HTTP 传输 + 同步引擎 + 端上灌入入口） |
| `app/` | Flutter 3.24 | **早期验证版**：先跑通"本地三表主副本 + 端上 30 秒 tick"，语义正移植进 Qt 版 |

## 4. 为什么不保留两套客户端

1. 4.1 的图与官方仓库都是 Qt，答辩时"两个客户端"会被问"到底哪个是交付物"。
2. 两套都要维护，而**状态机、事件 id、离线队列**三处一旦不同步就会出"端上显示 A、看板显示 B"。
3. Flutter 版的价值已经兑现：它证明了本地三表 + 端上 tick 可行，结论已写进报告 4.2.3（调度器放两处）。
