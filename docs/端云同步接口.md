# 端云同步接口（4.1 架构图第 5 层）

对应架构图的第 5 层"端云通信层（唯一网络出口）"。三条接口都是 `/api/v1` 下的**契约族**。

| 图上的路径 | 实现路径 | 方向 |
|---|---|---|
| `POST /v1/events` | `POST /api/v1/events` | 上行：本地事件队列补传 |
| `GET /v1/state?since=` | `GET /api/v1/state?since=` | 下行：按游标回灌 |
| `POST /v1/alarm` | `POST /api/v1/alarm` | 上行：端侧主动告警 |

## 1. POST /api/v1/events —— 批量上行

请求：

```json
{"events": [
  {"occurrence_id": "…", "action": "confirmed", "client_ts": "2026-11-10T08:03:12+08:00", "event_id": "…"}
]}
```

规则：

- `action` 只接受 `confirmed` / `snoozed` / `missed`（`notified`、`escalated` 由调度器产生，客户端传会被逐条拒绝）
- `event_id` 由**客户端生成**，重复即幂等（不会新增第二条）
- 逐条返回结果，客户端只需重发 `rejected` 里的条目

响应：

```json
{"accepted": 2, "duplicates": 1, "rejected": [{"index": 0, "occurrence_id": "…", "reason": "实例不存在"}], "server_ts": "…"}
```

## 2. GET /api/v1/state?since= —— 回灌

用途：换机、重装、家属代确认后，把服务端状态拉回本地。

```json
{"occurrences": [...], "records": [...], "next_since": "2026-11-09T13:16:42Z", "server_ts": "…"}
```

- `since` 为空或很早的时间 = 全量；把返回的 `next_since` 存下来，下次带上即可增量
- 游标基于 `occurrences.updated_at`；`records` 表没有 `updated_at`（追加式更正靠 `revision`），用 `created_at`

## 3. POST /api/v1/alarm —— 端侧告警

```json
{"kind": "sos", "note": "端上呼救", "device": "pixel-4a"}
```

`kind=sos` 走 `sos()`；其它 kind 走 `raise_alarm()`。返回 201 与告警对象，家属端长轮询会立刻收到。

## 实现注意（踩过的坑）

1. **不要在 `_post` 里再调 `self.body_json()`**：`_post` 开头已经把 body 读掉了，再读会等新字节直到超时（表现为请求挂住）。新路由必须复用已解析的 `body` 变量。
2. **不要把外层连接传给 `transition()`**：`transition()` 自己开连接并加锁，两层连接会互相等待。
3. 插入路由要**先定位 `_get` / `_post` 的函数范围**再插，`parts = p.strip("/").split("/")` 这类语句在 `_put/_patch/_delete` 里也有，直接用字符串锚点会插错位置。
