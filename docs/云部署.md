# 上云部署（本分支手工版，约 30 分钟）

> 这条分支只带 `server/`（后端 + 页面 + 测试）与 `tools/`，
> **没有** `deploy/setup.sh`、`deploy/caremate.service`、`tools/rotate_tokens.py`。
> 想要"一条命令装完 + 自动生成令牌"，用 main 分支的 `docs/云部署.md`。

## 0. 规格

- 1 核 2 G / Ubuntu 22.04 就够（纯 stdlib，没有 pip 依赖）
- 安全组放行 22 与 8000（没配域名时对外就是 `http://IP:8000`）

## 1. 上传

```bash
# 本机
scp -r server root@<IP>:/opt/caremate
# 服务器
ssh root@<IP>
apt update && apt install -y python3 tzdata curl
useradd -r -m -s /bin/bash caremate || true
chown -R caremate:caremate /opt/caremate
```

## 2. 令牌（必做，别用演示值）

`server/.env`（不进仓库）：

```
CAREMATE_ELDER_TOKEN=<8 位以上随机串>
CAREMATE_FAMILY_TOKEN=<另一个>
CAREMATE_COMMUNITY_TOKEN=<再一个>
CAREMATE_PAIR_CODE=<6 位数字>
```

生成随机串的两种办法：main 分支跑 `python tools/rotate_tokens.py --easy --length 8`，
或本机随便用什么生成 `23456789ABCDEFGHJKLMNPQRSTUVWXYZ` 里的 8 位（去掉 0O1Il 防抄错）。

```bash
chown caremate:caremate /opt/caremate/server/.env
chmod 600 /opt/caremate/server/.env
```

不配 `.env` 时服务会用代码里的 `app-elder-001` / `fam-demo-2026` / `comm-demo-2026` / `8823`，
挂公网等于把数据公开。

## 3. systemd

```bash
cat >/etc/systemd/system/caremate.service <<'UNIT'
[Unit]
Description=CareMate backend (single process, built-in scheduler)
After=network-online.target

[Service]
User=caremate
WorkingDirectory=/opt/caremate
Environment=PYTHONUNBUFFERED=1
EnvironmentFile=-/opt/caremate/server/.env
ExecStart=/usr/bin/python3 /opt/caremate/server/server.py --port 8000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
UNIT
systemctl daemon-reload && systemctl enable --now caremate
journalctl -u caremate -f        # 看到「调度器 开」即可
```

**改完代码重启别用 `restart`**：`Restart=always` 时旧进程没退净，新进程会
`启动失败：端口 8000 已被占用（[Errno 98]）`，要刷几十次才抢到。正确顺序：

```bash
systemctl stop caremate; sleep 2
ss -lntp | grep ':8000' || echo 端口已空
systemctl start caremate; sleep 3
curl -s http://127.0.0.1:8000/api/v1/health; echo
```

## 4. 对外

- 无域名：直接 `http://<IP>:8000`（家庭看板 `/dashboard`、老人端 `/app`、大屏 `/kiosk`）
- 要 HTTPS：域名 A 记录指过来，装 Caddy 反代 8000，Caddy 自动签证书；
  80/443 在安全组放行，服务器在大陆还要备案。

## 5. 验证

```bash
curl -s http://127.0.0.1:8000/api/v1/health
curl -s -H "X-Token: <老人令牌>" http://127.0.0.1:8000/api/v1/overview | head -c 200
curl -s -H "X-Token: app-elder-001" http://127.0.0.1:8000/api/v1/overview   # 应 401
```

## 6. 备份与清理

```bash
# 每天 03:00 备份（sqlite3 在线备份，不用停服务）
cat >/etc/cron.d/caremate-backup <<'CRON'
0 3 * * * caremate cd /opt/caremate && /usr/bin/python3 server/server.py --backup >> /opt/caremate/backups/cron.log 2>&1
CRON
# 演示数据炸成一片红条、想重来
sudo -u caremate /usr/bin/python3 /opt/caremate/server/server.py --reset-data --yes --seed
```


## 7. 改完代码怎么更新到云上（以及三个真坑）

云上的 `/opt/caremate` 是**部署那天的快照**，不会自己跟 GitHub 同步（国内机器直连 github.com 常常在 443 上超时，`git clone` 会挂很久）。改完这样发：

**本机（PowerShell）**，只传改过的文件：

```powershell
cd <本分支根目录>
scp server\server.py root@<服务器IP>:/root/server.py
scp -r server\web root@<服务器IP>:/opt/caremate/server/
```

**服务器上**，一条一条粘，别整块贴：

```bash
cp /root/server.py /opt/caremate/server/server.py && echo 已覆盖
```

```bash
chown -R caremate:caremate /opt/caremate && chmod -R a+rX /opt/caremate && echo 权限OK
```

```bash
/usr/bin/python3 -m py_compile /opt/caremate/server/server.py && echo 语法OK
```

```bash
systemctl stop caremate; sleep 2; ss -lntp | grep ':8000' || echo 端口已空; systemctl start caremate; sleep 3; curl -s -m 5 http://127.0.0.1:8000/api/v1/health; echo
```

最后一行要看到 `{"ok": true, ... "mode": "cloud", ...}`；看不到就 `journalctl -u caremate -n 25 --no-pager`。

### 三个坑（都真实踩过，症状很容易误判）

| 症状 | 真原因 | 正确做法 |
|---|---|---|
| 网站 502、`ss` 看不到 8000、日志说读不到 `server.py`（或 `bridge.py: Permission denied`） | **Windows 上 `tar` 打包记下的权限是 `0600`、属主 root**，解压后 `caremate` 用户没有读权限，启动即退出 | `chown -R caremate:caremate /opt/caremate && chmod -R a+rX /opt/caremate`，再 `systemctl start` |
| 报 `/opt/caremate/server.py: Permission denied`、`curl: (2) no URL specified`、`http://...: No such file or directory` | **整块命令粘进终端后被断行**，`&&` 后的半句被当成新命令执行 | 一条一条粘，确认提示符回到 `root@` 再粘下一条 |
| 改完重启后行为没变（像改动没生效） | 旧进程没退、新进程抢不到 8000，**对外服务的一直是旧进程** | `systemctl stop; sleep 2; ss -lntp \| grep ':8000' \|\| echo 端口已空; systemctl start`；起完 `curl health`，再验一条新接口 |

验"新代码真的上了"的窍门：挑一条**旧版会报错、新版才通**的请求。例如旧版 `/api/v1/auth/pair` 只认 `pairing_code`，对 `pair_code` 回 404：

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/auth/pair -H 'Content-Type: application/json' -d '{"pair_code":"<配对码>","label":"deploy-check"}'; echo
```

回 `201 {"token":"ses-..."}` 说明是新的；回 `404 {"error":"配对码不存在"}` 说明还在跑旧代码。
