# 作用：上云部署完整手册：选机、无域名/有域名两条路、令牌、systemd、HTTPS、备份、防火墙、排错
# 上云部署（从买机器到 HTTPS 可用）

> 目标：把 `server/` 放到一台公网服务器上，得到一个**不依赖你电脑**的地址。
> 两条路：**A 没域名**（10 分钟，`http://IP:8000`）/ **B 有域名**（40 分钟，`https://你的域名`）。

## 0. 先选机器

| 选择 | 价格 | 适合 | 注意 |
|---|---|---|---|
| **Oracle Cloud 免费 ARM** | 0 元（永久免费额度） | 想白嫖、能接受注册麻烦 | 选 Ampere A1（4 核 24 G 的免费额度里取 1–2 核）、Ubuntu 22.04；开机后在安全列表放行端口 |
| **阿里云/腾讯云 学生机** | ¥9–15/月 | 国内访问最快 | 国内机器**绑域名要备案**；只用 IP:端口 不用备案 |
| **腾讯云/阿里云 轻量** | ¥24–40/月 | 稳定、控制台简单 | 同上 |
| **海外 VPS（Vultr/DigitalOcean）** | $5–6/月 | 要域名又不想备案 | 国内访问延迟高一些 |

规格够用就行：**1 核 1 G / Ubuntu 22.04 / 20 G 盘**。本项目零第三方依赖，只吃内存几十 MB。

> 需要放行的端口：`22`（SSH），有域名再加 `80/443`；没域名就用 `8000`。
> 国内厂商在"安全组/防火墙"里放行，Ubuntu 里还要 `ufw`（见第 6 节）。

## 1. 上传代码

```bash
# 在你电脑上（仓库根目录）
scp -r server root@服务器IP:/opt/caremate
ssh root@服务器IP
apt update && apt install -y python3 python3-venv curl rsync ufw
```

> 只传 `server/` 就够（页面在 `server/web/` 里）。`tools/` 里的脚本可选：需要轮换令牌时再传。

## 2. 令牌（必做，别跳）

演示令牌（`app-elder-001` / `fam-demo-2026` / 配对码 `8823`）挂公网等于裸奔。两种做法：

**做法一（推荐）**：本地生成，只把 `.env` 传上去

```bash
# 本地仓库根目录
python tools/rotate_tokens.py            # 会打印三个令牌 + 配对码，并写 server/.env
scp server/.env root@服务器IP:/opt/caremate/.env
```

**做法二**：在服务器上生成

```bash
cd /opt/caremate
python3 - <<'PY'
import secrets
print("CAREMATE_ELDER_TOKEN=" + secrets.token_urlsafe(24))
print("CAREMATE_FAMILY_TOKEN=" + secrets.token_urlsafe(24))
print("CAREMATE_COMMUNITY_TOKEN=" + secrets.token_urlsafe(24))
print("CAREMATE_PAIR_CODE=" + "".join(secrets.choice("0123456789") for _ in range(6)))
PY
# 把输出粘进 /opt/caremate/.env，一行一个
chmod 600 /opt/caremate/.env
```

服务启动时会自己读 `/opt/caremate/.env`（`server.py` 的 `load_dotenv()`），不用改任何代码。

## 3. systemd 常驻（单进程）

```bash
# 建服务账号
useradd -r -s /bin/false caremate 2>/dev/null || true
chown -R caremate:caremate /opt/caremate
chmod 600 /opt/caremate/.env && chown caremate /opt/caremate/.env

# 装单元
cp /opt/caremate/deploy/caremate.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now caremate
systemctl status caremate --no-pager
journalctl -u caremate -f          # 看到「调度器 开」「已启动」就对了
```

**为什么必须单进程**：调度器跑在进程内，多 worker 会让提醒发两遍、升级重复触发。

## 4. 两条路：不绑域名 / 绑域名

### A. 不绑域名（最快，适合演示）

让服务直接监听公网：

```bash
# 改单元里的监听地址（默认 127.0.0.1 只给反代用）
sed -i 's/--host 127.0.0.1/--host 0.0.0.0/' /etc/systemd/system/caremate.service
systemctl daemon-reload && systemctl restart caremate

# 放行端口
ufw allow 22/tcp && ufw allow 8000/tcp && ufw --force enable

# 验证
curl -s http://127.0.0.1:8000/api/v1/health
```

外网访问：`http://服务器IP:8000/dashboard`（老人端 `/app`，kiosk `/kiosk`）。
缺点：**是 HTTP 明文**，令牌会以明文过网络；只适合短期演示。

### B. 绑域名 + 自动 HTTPS（推荐）

1. 域名 A 记录指向服务器 IP（`ping 你的域名` 能出这个 IP 就算生效）
2. 装 Caddy 并换域名：

```bash
apt install -y debian-keyring debian-archive-keyring apt-transport-https gnupg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' \
  | gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' \
  > /etc/apt/sources.list.d/caddy-stable.list
apt update && apt install -y caddy

sed 's/caremate\.example\.com/你的域名/' /opt/caremate/deploy/Caddyfile > /etc/caddy/Caddyfile
systemctl reload caddy
journalctl -u caddy -f        # 等 "certificate obtained successfully"
```

3. 验证：

```bash
curl -s https://你的域名/api/v1/health
curl -s -H "X-Token: 你的家属令牌" https://你的域名/api/v1/overview | head -c 200
```

> 一键脚本：`bash /opt/caremate/deploy/setup.sh 你的域名`（或 `bash deploy/setup.sh --no-domain`）。
> 国内服务器绑域名**必须先备案**，否则 80/443 会被拦；不想备案就用海外机或只走 IP:8000。

## 5. 备份（别只留在云上）

```bash
mkdir -p /var/backups/caremate
# 每天 3 点在线备份（SQLite .backup，不会锁库）
(crontab -l 2>/dev/null; echo '0 3 * * * cd /opt/caremate && python3 server.py --backup >> /var/log/caremate-backup.log 2>&1') | crontab -
# 每天 4 点把最近 7 天备份同步回你电脑（在本地跑，或用 rsync 到另一台）
```

从本机拉回：

```bash
scp root@服务器IP:/opt/caremate/backups/caremate-*.db  ./本地备份/
```

## 6. 安全加固（五分钟做完）

```bash
# 只开必要端口
ufw default deny incoming
ufw allow 22/tcp
ufw allow 80,443/tcp     # 有域名
ufw --force enable

# SSH 改端口 + 禁密码登录（可选但建议）
sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
systemctl restart ssh

# 自动安全更新
apt install -y unattended-upgrades && dpkg-reconfigure -plow unattended-upgrades
```

再确认三件事：

1. `/opt/caremate/.env` 权限 `600`、属主 `caremate`，**不进 git**（`.gitignore` 已覆盖）
2. `/api/v1/health` 能匿名访问没问题，但 `/dashboard` 没令牌看不到数据
3. 别用 root 跑服务（单元里已是 `User=caremate`）

## 7. 排错

| 现象 | 原因 | 处理 |
|---|---|---|
| `systemctl status` 显示 failed | 看 `journalctl -u caremate -n 50` | 多为 `.env` 权限或路径错 |
| 本机 curl 通、外网不通 | 安全组/ufw 没放行 | 云控制台 + `ufw status` 两处都要开 |
| 域名 502 | Caddy 起来了但后端没起 | `systemctl status caremate` |
| 域名证书申请失败 | A 记录没生效 / 80 被墙 / 备案未过 | `dig 你的域名`、`journalctl -u caddy` |
| 提醒发两遍 | 起了多个进程 | `systemctl status caremate` 应只有 1 个；别用 gunicorn 多 worker |
| 502 但 token 正确 | 服务监听 127.0.0.1 却直连 IP | 走域名（Caddy）或按 A 路径改 `0.0.0.0` |
| 数据没了 | 重装/删盘 | 恢复 `/var/backups/caremate/*.db` 到 `/opt/caremate/caremate.db` |

## 8. 与 Tailscale Funnel 方案怎么选

| | Tailscale Funnel（现在用的） | 云服务器（本文） |
|---|---|---|
| 花钱 | 0 | ¥0（Oracle）～¥40/月 |
| 依赖你电脑 | **是**（关机就 502） | 否，7×24 |
| 地址 | 固定 `*.ts.net` | 固定（IP 或域名） |
| HTTPS | 自动 | Caddy 自动 |
| 流量 | 1 GB/月 | 看你买的套餐 |
| 适合 | 演示、答辩前给你和老师看 | 长期跑、真实使用 |

**建议**：答辩前用 Tailscale（已经配好）；如果要长期留着给人用，按本文上云，然后把 `main` 里的地址换掉。

## 边界（如实说）

单机无高可用：服务器重启、欠费、磁盘满都会让提醒停摆；SQLite 单写，QPS 上限约百级；
没有多租户隔离（只有"家属-老人"绑定）。这些在论文里要写清，不要承诺 7×24。
