## 二、修掉的真 bug（都跑过验证）

### 服务端（`server/server.py`、`server/v1_adapter.py`）

1. **时区其实是假的**：Windows 上的 Python 没有 tz 数据库，`ZoneInfo` 抛异常后被兜底成固定 +8，`CAREMATE_TZ` 写什么都当上海。现改为：先用 `ZoneInfo`，失败后用内置的夏令时规则表（美/欧/澳/新西兰），`/api/v1/health` 多回 `tz_source`、`tz_note`、`utc_offset_min`，看板能看出用的是哪种时区。
2. **一条坏计划能让所有老人的提醒停摆**：`rule={"kind":"monthly","day":"x"}` 以前能存进去，下一次调度 `int("x")` 抛异常，整个 tick 中断。现在建计划时就校验数值（day/n/days/offset），调度器对每个老人、每条实例都各自 try/except，坏数据只跳过自己。
3. **越权**：社区只读令牌能确认/记未确认任何人的提醒，能上报"有人活动"把无动静告警压掉，能改计划、删记录；`/v1/*` 侧按整数 id 反查也不校验归属。现在所有写路径先校验资源归属，再校验角色。
4. **手机端看不到家属的动作**：`transition()` 改状态时不更新同步序号，家属在网页确认、调度器升级，手机增量拉取都拿不到。现在同事务里 bump 序号。
5. **确认会被调度器覆盖**：`commit()` 原来在锁外，调度线程能读到旧状态把 confirmed 改成 missed。现在提交也在锁内，并加了状态迁移校验（已确认的不能再被改成 notified/missed，但"未确认 → 确认"仍允许，补记是正当操作）。
6. **同一个计划一天两条提醒，确认写错条**：`/v1` 的实例 id 解析对每行都试序号，20:00 的确认被记到 08:00。现在按本地日期算精确序号。
7. **增量同步漏数据**：`/v1/state` 先 `LIMIT 800` 再按游标过滤，第 801 条以后的新提醒永远拉不到；游标只到秒，同秒多行永远翻不过去。现在游标改 (时间, id) 复合键，分页在 SQL 层做，并回 `has_more`。
8. **配对本来是死路**：`/v1/pair` 被通用 401 挡在配对逻辑前面，新设备/换机根本没有令牌可带。现在配对在鉴权之前，并按来源 IP 限速（10 分钟 10 次，不信任 `X-Forwarded-For`）。
9. **本地 00:00–07:59 的提醒确认不了**：按 `due_at` 的 UTC 日期前缀匹配本地 slot，必然匹配不上。现在按 `slot_local` 精确匹配。
10. **参数没校验**：`?days=abc` 以前 500 并回显 `invalid literal for int()`；现在统一走 `_qi()` 回落默认值并夹区间，非法游标、非法 level、非法 JSON 都回 4xx。
11. **空标题计划**：`plans` 缺 `title` 也能建成，老人端会念出没有药名的提醒。现在 422。
12. **记录只改备注会把数值清空**：`PATCH /v1/records/<id> {"note":"x"}` 以前生成 value/unit 为 NULL 的新版本。现在只更新真的传了且非空的字段。
13. **暂停/删除计划后还在提醒**：调度器查询不 join 计划的 active。现在 join，并且暂停日期生效。
14. **无动静告警永远不触发**：调度器自己写的 notified/escalated 事件把"有动静"计时器清零。现在只统计真人动作（`actor<>'' AND actor<>'scheduler'`）。

### 网页端（`server/web/*.html`）

1. **存储型 XSS**：计划标题、剂量、记录备注、告警 message 以前直接拼进 `innerHTML`，社区令牌可注入脚本盗家属令牌。现在全部 `esc()`，并用 Chrome 远程调试做了端到端验证（载荷进了库但页面里是转义文本）。
2. **呼救假成功**：kiosk 页面 `.catch(()=>{})` 且不看 `r.ok`，没发出去也显示"已通知家里人"。现在失败会明确提示再按一次或直接打电话。
3. **断网谎称"记在本机"**：老人端点确认失败时提示先记本机，其实没有队列。现在有本地队列（localStorage），联网自动补记，并回执"已补记 N 条"；非网络错误（401/422）不再谎称。
4. **UTC 当本地用**：看板用 UTC 日期配本地时分判断"未到点"，凌晨会差一天；老人端提交时间用 `toISOString().slice(0,16)`，比本地时间差 8 小时。现在统一用本地时间。
5. **点"等会儿"卡片立刻重现**：过滤条件没排除 `snoozed`，状态表也缺这个状态。已补。
6. **令牌无效后旧数据还挂着**：清空令牌后表格仍显示上次的数据。现在 `clearAll()` 清空所有分区。
7. **无令牌时每 3 秒打一次 401**：改成长轮询前先看有没有令牌，没有就等 5 秒。
8. **刷新页面会重弹历史 SOS**：告警序号从 0 开始，首轮把历史全放一遍。现在首轮只对齐序号不重放。
9. **撤销条提前消失**：连按两条时清的是新对象的定时器。已修。
10. **呼救键太小**：60px/18px 不满足无障碍自检（≥84px），已改 84px/26px，并把呼救键纳入自检。

### 客户端代码

- Flutter（`app/`）：待办列表以前不看"是否到点"、还按时间倒序排，上午 9 点会显示 20:00 的药且能提前确认；点过"稍后提醒"后该条本次运行再也不会出现；本地库读回来把 rule 硬编码成"每天"，周计划变每天。三处都改了，`flutter analyze` 无问题。
- Qt（`qt/`）：`ReminderModel` 里 `Occ::dose` 字段不存在（编译必失败）、`m_store` 从未创建（本地主副本是死代码、一调用就空指针）、`m_saveTimer` 没连 `persistNow`（永不落盘）、增量同步整表替换（会抹掉当天其它提醒）、到点后 `recompute()` 只收 pending（老人反而看不到确认按钮）、同步途中按呼救被静默丢弃、`CMakeLists` 用 Qt5 写法设置 Android 包目录（清单和 JNI 从没进过 APK）。均已修，但**没有 Qt SDK，未编译验证**。

### 工具

- `tools/collect_evidence.py`：原来路径写死在别的目录、只跑六套、全部跳过也报"合计 0/0 通过"且退出码 0（假证据）。现在自动定位仓库、九套齐全、缺套件或后端没起都退出 2、没取到结果或有用例失败退出 1，并会自动用临时库起后端跑完再关。实跑 77/77。
- `tools/gen_index.py`：`git ls-files` 失败时会把两份索引覆盖成 0 条。现在检查退出码、空结果直接中止，不写坏的。
- `tools/rotate_tokens.py`：轮换令牌会整文件重建 `.env`，把 `CAREMATE_DB` 等手工加的配置抹掉。现在只替换四个键，其余原样保留。
- `tools/publish.py` / `tools/sync_branches.py`：提交失败仍会推送/仍报"已同步"且退出码 0。现在提交失败就中止推送，推送失败单独标状态并返回 1。

## 三、没有验证 / 还没修的

- **Qt 侧改动没有编译**：本机没有 Qt SDK（下载镜像给的包校验不过，之前已放弃），只做了代码级修复，`qt/` 仍属骨架。
- **给颐伴的补丁（`integration/yiban_client/对接后端.patch`）里已知一处问题**：建表列名与 `INSERT OR REPLACE INTO plans(planId, json)` 不一致，导致本地库写不进去。补丁是给对方的 diff，直接改文本会让上下文对不上、打不上；已在对接说明里写清，等对方合并后我们再发一版修正补丁。
- **硬件链路**：`home/sensor/presence` 目前没有订阅方，雷达数据到不了服务端（久未活动告警缺输入）；固件的雷达判断是演示级；ESP32、MQTT broker、树莓派桥都没在真机上跑过。
- **APK 没装到真机**：构建通过、分析无问题，但没有真机安装验证。
- **云部署脚本没在真服务器上跑过**：本机没有云主机，`deploy/setup.sh` 只做了语法检查和本地演练。
